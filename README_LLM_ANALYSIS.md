# Документация для анализа логов игры с помощью LLM

Этот документ предоставляет всю необходимую информацию для анализа лог-файлов игры "Silent Red Storm" с целью оценки эффективности и логики AI-стратегий.

## 1. Обзор игры и ключевые сущности

- **`Ship` / `Submarine`**: Основные боевые единицы (корабли и подводные лодки). Управляются либо игроком, либо AI.
- **`Vehicle`**: Базовый класс для всех движущихся объектов, включая корабли и торпеды.
- **`Torpedo`**: Оружие, выпускаемое кораблями. Имеет собственную (обычно простую) логику поведения.
- **Стратегия (Strategy)**: "Мозг" объекта, управляемого AI. Определяет его поведение. Стратегии могут быть написаны на TypeScript или с использованием специального языка DSL.

## 2. Формат логов

Логи пишутся в текстовый файл. Каждая строка имеет следующий формат:

`[TIMESTAMP] [TAG] [LEVEL] MESSAGE | Context: { ... }`

- **`TIMESTAMP`**: Время события (ISO 8601).
- **`TAG`**: Категория события. Особенно важны теги, связанные с AI:
    - `AI_Vehicle 1`: Общее событие, связанное с объектом ID=1.
    - `AI_DECISION_Vehicle 1`: Событие, связанное с принятием решения объектом ID=1.
- **`LEVEL`**: Уровень важности (`INFO`, `WARN`, `ERROR`, `DEBUG`).
- **`MESSAGE`**: Описание события.
- **`Context`**: (Опционально) JSON-объект с детальными параметрами события.

**Пример лога решения AI:**
```
[2025-11-04T19:27:28.878Z] [AI_DECISION_Vehicle 1] [DEBUG] Eval IF: Condition: "best_target IS_PRESENT AND weapon_I IS_READY AND distance_to(best_target) < 800" -> true
```
Этот лог означает, что для объекта `Vehicle 1` условие в блоке `IF` его DSL-стратегии было оценено как `true`.

## 3. Система обнаружения (Сенсоры)

Обнаружение противника основано на **шуме**.

- Каждый корабль издает шум в зависимости от своей скорости.
- Другие корабли "слышат" этот шум. Сила полученного сигнала зависит от расстояния.
- В зависимости от силы сигнала цель попадает в одну из **зон обнаружения**:

| `DetectionState`      | Уровень | Описание                                     |
| --------------------- | ------- | -------------------------------------------- |
| `NO_CONTACT`          | 0       | Контакта нет.                                |
| `ZONE_1_UNCERTAIN`    | 1       | **Ненадежный контакт**. Есть примерное направление, но точные координаты неизвестны. Атака невозможна. |
| `ZONE_2_LOCALIZED`    | 2       | **Локализованный контакт**. Известны точные координаты, курс и скорость. Атака возможна. |
| `ZONE_3_IDENTIFIED`   | 3       | **Идентифицированный контакт**. Известен тип корабля и его состояние (например, здоровье). |

Для атаки цель должна быть как минимум в `ZONE_2_LOCALIZED`.

## 4. Система DSL-стратегий (Ключевая информация)

Поведение AI описывается с помощью простого языка (DSL) в формате YAML. Это позволяет быстро создавать и менять тактики.

### Структура DSL

```yaml
strategy: "Имя стратегии"
description: "Описание того, что она делает."

# Фаза анализа: сбор информации, оценка обстановки
ON ANALYZE:
  - FIND:
      # ... параметры поиска ...

# Фаза действий: принятие решений на основе анализа
ON ACTION:
  IF:
    condition: # ... условие ...
    actions:
      - Action:
          # ... действие ...
  ELSE IF:
    # ... другой блок ...
  ELSE:
    # ... действия по умолчанию ...
```

### Фаза `ON ANALYZE`

На этом этапе AI "осматривается" и ищет цели.

- **`FIND`**: Основная команда для поиска объектов.
    - **`best_target`**: (или любое другое имя переменной) Имя, под которым будет сохранена найденная цель.
    - **Параметры `FIND`**:
        - `type`: Тип цели для поиска (`ship`, `submarine`, `torpedo`).
        - `range`: Максимальная дистанция поиска.
        - `detection_zone`: Минимально требуемая зона обнаружения (например, `1` для `ZONE_1_UNCERTAIN`).

**Пример:**
```yaml
ON ANALYZE:
  - FIND:
      best_target:  # Найти цель и сохранить как 'best_target'
        type: ship
        range: 2000
        detection_zone: 1
```

### Фаза `ON ACTION`

На этом этапе AI действует на основе информации, собранной в `ON ANALYZE`.

- **`IF / ELSE IF / ELSE`**: Стандартная логическая структура для принятия решений.

### Условия (`condition`)

Используются для проверки состояния мира.

| Условие                         | Описание                                                              |
| ------------------------------- | --------------------------------------------------------------------- |
| `variable IS_PRESENT`           | `true`, если цель, найденная в `ON ANALYZE` (например, `best_target`), существует. |
| `variable IS_NOT_PRESENT`       | `true`, если цель не найдена.                                         |
| `weapon_I IS_READY`             | `true`, если оружие типа I (торпеда) готово к выстрелу. (`weapon_II`, `weapon_III` для других типов). |
| `distance_to(variable) < 800`   | `true`, если дистанция до цели `variable` меньше 800. Поддерживаются операторы `<`, `>`, `<=`, `>=`, `==`, `!=`. |

Условия можно комбинировать с помощью `AND` и `OR`.

### Действия (`Action`)

Команды, которые выполняет AI.

| Действие                  | Описание и параметры                                                                                                   |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `ATTACK`                  | Атаковать цель. <br> - `with`: переменная цели (например, `best_target`). <br> - `torpedo`: тип оружия (`weapon_I`, `weapon_II`, ...). <br> - `predict_lead_time`: время упреждения в секундах (на сколько секунд "вперед" целиться). |
| `CHASE`                   | Преследовать цель. <br> - `target`: переменная цели. <br> - `distance`: дистанция, на которой нужно держаться от цели. <br> - `power`: мощность двигателя (0-6). <br> - `depth`: глубина (для подлодок). |
| `PATROL`                  | Патрулировать. В текущей реализации просто движется прямо. <br> - `power`: мощность двигателя. |
| `EVADE`                   | Уклоняться от угрозы. <br> - `from`: переменная угрозы. <br> - `distance`: на какую дистанцию оторваться. <br> - `power`: мощность двигателя. |
| `HOLD_POSITION`           | Остановиться и удерживать позицию. |

### Пример DSL-стратегии для анализа

Вот код стратегии **"Агрессивный охотник"**, который используется в тестовом сценарии:

```yaml
strategy: "Агрессивный охотник"
description: "Атакует ближайшие цели"

ON ANALYZE:
  - FIND:
      best_target:
        type: ship
        range: 2000
        detection_zone: 1

ON ACTION:
  IF:
    condition: best_target IS_PRESENT AND weapon_I IS_READY AND distance_to(best_target) < 800
    actions:
      - Action:
          ATTACK:
            with: best_target
            torpedo: weapon_I
            predict_lead_time: 5
  ELSE IF:
    condition: best_target IS_PRESENT
    actions:
      - Action:
          CHASE:
            target: best_target
            distance: 400
            power: 6
            depth: 100
  ELSE:
    actions:
      - Action:
          PATROL:
            power: 3
```

**Анализ этой стратегии:**
1.  **Каждый цикл анализа**: Ищет любой корабль в радиусе 2000, который обнаружен хотя бы в зоне 1.
2.  **Каждый цикл действий**:
    - **Если** цель найдена, оружие готово и дистанция меньше 800, **атаковать** торпедой с упреждением в 5 секунд.
    - **Иначе, если** цель просто найдена (но, например, оружие не готово или дистанция > 800), **преследовать** ее на полной мощности, пытаясь сократить дистанцию до 400.
    - **В противном случае** (если целей нет), просто **патрулировать** на 3-й мощности.
